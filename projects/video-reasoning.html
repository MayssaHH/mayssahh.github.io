Structured Graph-Based Retrieval for Video Reasoning

Turning long-form videos into temporal, discourse-aware multimodal graphs for explainable retrieval and question answering.

Research project · American University of Beirut · Multimodal Retrieval / Video Understanding / Graph-Based Reasoning

My contribution: graph design, retrieval, implementation, and development of the multimodal processing pipeline.

Presented at MenaML 2026 at KAUST, Saudi Arabia.

Motivation

Video knowledge is rarely contained in one modality. A useful detail may be spoken, shown as text on a slide, visible in a UI, or only meaningful because of when it appears relative to the rest of the video. Flattening a video into a transcript loses visual evidence; treating frames independently loses narrative and temporal structure.

This project asks whether video can instead be represented as structured evidence: a graph that preserves what was said, what was shown, when it happened, and how pieces of information relate to each other.

Core idea: transcript first

The central design choice is to build the graph from the transcript first. Timestamped speech segments form the semantic and temporal backbone of the video. Visual information is then aligned to that backbone by time and used to enrich it with captions, OCR, entities, and scene-level information.

This gives the system a representation that follows the narrative flow of the video while still incorporating evidence that exists only visually.

From video to multimodal graph

A YouTube URL is ingested using yt-dlp and ffmpeg. The system extracts audio, frames, clips, and scene boundaries, then produces timestamped speech segments using Whisper. In parallel, visual clips are analyzed for captions, entities, scene type, and OCR.

The graph is then constructed around four main node families:

Transcript nodes represent timestamped spoken segments.

Visual nodes store aligned captions, OCR, scene cues, and frame-level descriptions.

Topic nodes represent higher-level semantic segments and discourse structure.

Entity nodes represent canonical people, places, objects, organizations, and concepts mentioned in the video.

Relations

The representation goes beyond adjacency. Transcript segments are connected temporally with TEMPORAL_NEXT; visual evidence is connected through ALIGNED_TO; semantic segments connect to topics through BELONGS_TO_TOPIC; entities are attached with CONTAINS_ENTITY; and discourse relations capture links such as EXPLAINS, EXAMPLE_OF, SUPPORT, COUNTER, CAUSES, STEP_BEFORE, ELABORATES, and DEFINES.

Retrieval

Retrieval happens in stages rather than as a single nearest-neighbor lookup. A query first runs through a hybrid retrieval layer that combines semantic similarity with keyword matching. The strongest results become seed evidence nodes, which are then expanded through the graph to retrieve related topics, entities, neighboring transcript segments, and aligned visual evidence.

The resulting evidence set is reranked and assembled into context for answer generation. Each supporting item retains its source video and timestamp so the final answer can be traced back to evidence.

Why hybrid retrieval?

Embedding search is useful for conceptual matches, but exact names, terms, acronyms, and text visible on screen can be easy to miss. Combining semantic and lexical retrieval protects both kinds of signal.

Why k-hop expansion?

The most semantically similar node does not always contain the full answer. Relevant context may live one or two graph edges away: an explanation, supporting example, related topic, aligned slide, or neighboring segment. Expanding around high-confidence seed nodes lets the system retrieve that supporting structure explicitly.

Cross-video search

The same retrieval abstraction extends beyond a single video. Node embeddings are precomputed and cached during ingestion, allowing a query to search across a corpus of processed videos, retrieve evidence from multiple sources, and preserve which video and timestamp each item came from.

This turns the system from a single-video QA tool into a searchable multimodal video corpus in which evidence from different videos can be brought together through a shared retrieval interface.

Explainable video QA

The output is not only an answer. It includes the evidence used to construct that answer: transcript excerpts, visual evidence, OCR, timestamps, node identifiers, and the relevant neighborhood of the graph. The goal is to make retrieval inspectable rather than treating the reasoning context as an opaque bundle of chunks.

Prototype system

The system is implemented as an end-to-end application with a FastAPI backend and a React interface. The UI synchronizes the video, transcript, interactive graph, query, and ranked evidence so that the user can move directly between an answer and the supporting video context.

The implementation also uses precomputed embeddings, caching, parallel visual processing, and a lightweight ffmpeg-based ingestion path to reduce query-time and ingestion overhead.

Evaluation framework

At the current stage, the project defines an evaluation framework rather than reporting a complete quantitative benchmark. Retrieval quality can be measured using Recall@5/10, MRR, nDCG@k, timestamp overlap, and evidence redundancy. Answer quality can be evaluated through human-rated correctness and faithfulness, citation precision, and temporal error. Efficiency can be measured through index-build time, p50/p90 query latency, and memory footprint.

Limitations and future directions

Discourse grounding. Discourse relations are currently inferred and could be strengthened with more explicit structural constraints.

Cross-video linking. Retrieval already spans multiple videos, but richer explicit links based on shared entities and aligned topics would make the corpus graph more coherent.

Benchmarking. The next important step is systematic evaluation on established VideoQA benchmarks together with human evaluation of evidence faithfulness.

Interactive refinement. User-driven graph corrections and active-learning loops could make the representation progressively more reliable.
